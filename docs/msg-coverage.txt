fix(rules): run best-practice rules too, because the tool was seeing two thirds of the page

Found by building a realistic marketing page (nav, hero, form, table, inline script) and
asking what the tool did NOT report. A page with h1 followed by h3, content outside any
landmark, and an onclick div came back with only image-alt, link-name and frame-title.

Cause: runOnly used the five WCAG tags. That is 70 of 105 rules, and it silently excluded 30
best-practice rules - heading-order, region, landmark-one-main, page-has-heading-one,
aria-allowed-role, empty-heading, skip-link, tabindex, label-title-only and the rest.

Those rules are excluded from a WCAG conformance claim for a good reason. This tool does not
make conformance claims - it reports quality and prints the caveat every run - so excluding
them meant reporting on two thirds of the page while sounding complete.

Effect on the known-bad fixture: region x6 (moderate, 2 each) added, damage 35 -> 47, score
53 -> 46. No input changed. That is a measurement working correctly, and it carries a warning
worth writing down: a score is only comparable to another score from the same rule set. Every
report prints engine and score-spec versions; a baseline must record both, or its delta means
nothing. Recorded in SCORE-SPEC.md next to the re-audited fixture.

New docs/COVERAGE.md states what a run inspects and what it cannot: 100 of 105 rules, five
excluded and why; contrast, styles, page-assigned ids and the rendered DOM of a hydrated app
are all undecidable from a file, and a file-based score is a floor rather than a measurement.

New test asserts the rule set rather than a number: content outside a landmark and a skipped
heading level must both be found. Tests 60 (was 59). README quotes the new output.
