# ADR 0004 — One name, one host: MR-Spark, `mr-spark`, and a free Pages address

**Date:** 2026-11-07
**Deciders:** Mohammad Rayhan (owner), with the trade-offs measured by Arena
**Supersedes:** nothing. It closes the naming question left open in `docs/PLAN.md` §"open questions" #3,
and it is the first exercise of the rule `docs/HOSTING.md` §5.5 states — moving the schema host is a
format amendment — so it records what that rule cost in practice.

## Context

Three things were named `web-spark`/`webspark` for different reasons, and only the first was a choice.

1. **The product.** `src/config/brand.js` said `NAME = 'web-spark'`. The owner wanted the authorship in the
   product name: **MR-Spark**, for Mohammad Rayhan.
2. **The npm package.** `package.json` said `webspark`. That name is **not ours and never was**: on npm it
   has belonged to an unrelated Node blog engine since April 2019 (registry checked 2026-11-07, maintainer
   `windyfancy`, last published 2022). So `README.md`'s `npx webspark check <url>` and
   `import … from 'webspark/formats'`, and `docs/HOSTING.md` §2's `./node_modules/webspark/schema/…`, were
   all instructions to install somebody else's code. `mr-spark` and `mrspark` are both unclaimed.
3. **The schema host.** `SCHEMA_HOST` was `https://web-spark.dev/schema` — an address nobody owns, had ever
   owned, or had tested. It is not a comment about where files sit: the string is each schema's `$id`, the
   target of every `$ref` between them, and the required `const` in `$schema` of every document
   (`src/formats/common.js`). Until this change, every document in the repository named a dead URL, and the
   only reason nothing broke is that nothing outside the repository has ever fetched it.

Renaming the product without settling the host would have produced the worst combination: a new name whose
documents still name an address owned by nobody, in a format whose next change is supposed to be the last
one that costs anything.

## Decision

**The product is MR-Spark; the package is `mr-spark`; the command stays `spark`; the schema host is
`https://mr-spark.pages.dev/schema`.** All in one pass, so that no artifact, report header, or document
example carries a mixture.

- **Name in one place.** `brand.js` `NAME` is the only definition. Four copies of the string had
  accumulated — the terminal report header, `lower()`'s refusal, the provenance line `emit` writes into
  every page and stylesheet it produces, and the schema titles — and all four now read `NAME`. The last
  one matters most: `generated by MR-Spark from … · ir <hash>` is a claim inside the artifact, and a
  rename that missed it would keep shipping the old name inside other people's HTML.
- **`spark` stays the command.** The signature is in the product name, the byline in the report and the
  emitted artifact. Charging users an extra five characters per invocation to credit an author is the
  wrong place for an ego mark, and `spark.config.json` keeps working for anyone who has one.
- **`mrspark` ships as a pointer.** Publish both: `mr-spark` is the package, `mrspark` re-exports it so a
  mistyped install cannot land on an unrelated project.
- **The host is a free Cloudflare Pages project**, deployed by `.github/workflows/pages.yml` from
  `npm run schema:bundle` — the committed `schema/` bytes, the index page, and a `_headers` file derived
  from the same `headersFor` the local server answers with. `verify` after the deploy checks bytes *and*
  headers, so the contract is tested against the real host rather than assumed from documentation.
- **`NOTICE` names the copyright holder**: Mohammad Rayhan and MR-Spark contributors.

## Why this host, and not the others

- **Keep `web-spark.dev` in the const and deploy elsewhere.** Rejected. It is a dead address in a required
  field, which is what we had; "somebody may buy it later" is not a plan, it is a liability — a stranger
  owning the URL in every document's `$schema` would control what those documents resolve to.
- **GitHub Pages (`raydirect.github.io/mr-spark/schema`).** Rejected as canonical, kept as a possible
  mirror. It cannot set `Content-Type`, so it would serve `application/json` where §5.3 makes
  `application/schema+json` part of the interface, and the URL embeds `org/repo` — which `docs/HOSTING.md`
  refuses as a permanent host precisely because a repo rename or archive would break documents.
- **`cdn.jsdelivr.net/gh/<org>/<repo>@<tag>/schema/…`.** Zero infrastructure and immutable by tag, but the
  same two defects: no media-type control, and the address is a coordinate inside a repository rather than
  a home. It remains the emergency fallback.
- **An environment override for `SCHEMA_HOST`.** Rejected, and this is the one worth stating loudly. A
  const that varies with the environment is not a const: `MR-Spark` documents would validate on the machine
  that generated them and nowhere else, which is the two-resolvers failure (ADR 0002) with a shell variable
  added. `formats:check` pins the bytes, `bundle` ships them, `verify` tests them over the wire; that is
  the whole flexibility a format identifier should have.
- **Two accepted `const` values, old host and new.** Rejected. It would have spared our six own documents a
  rewrite by making "which host is canonical" ambiguous forever.
- **Buy a domain first.** Rejected as a blocker, kept as the open item. The point of the test host is to
  make the address real while it costs nothing; the domain is the decision that makes it durable, and
  §5.5's cost estimate now exists rather than being guessed at.

## Consequences

**The amendment is cheap and the inventory was small, which is the entire argument for doing it now.**
Rewritten in this pass: one line of code, six generated artifacts, six authored documents
(`src/config/tokens.json` plus five fixtures under `test/fixtures/docs/`), and eleven prose mentions across
seven files. Every one of those was ours. The next time this happens there may be a stranger's documents in
the list, and the honest migration step for them is "edit one string", which is only a small favour if the
host has not changed twice by then.

**Documents naming the old address are now invalid, and that is the intended behaviour.** A document whose
`$schema` is `https://web-spark.dev/schema/scene-0.1.json` fails the const check rather than being
accepted under two vocabularies. Nothing outside this repository has ever had one.

**`schema/` stopped being theoretical.** There is now a URL that answers, a workflow that publishes to it,
and a nightly job (`watch`) that fails if its bytes or headers drift. `docs/HOSTING.md` §5.4 asked for
exactly that and had no way to get it while the host was fictional.

**The host is rented, not owned, and that limits what we may claim.** A `pages.dev` subdomain belongs to a
Cloudflare project name: it can be renamed, deleted, or stranded by a terms change. §5.1 promises a
versioned file is immutable *forever*, and no free subdomain can honestly keep a promise measured in
decades. Two things follow, both recorded where they will be read: `docs/HOSTING.md` §6 labels the whole
setup "a host we are renting for free", and the domain purchase stays an open row in
`docs/PHASE-PLAN.md` §9 — with the note that moving the const again is an amendment, so the right time to
buy the domain is before anyone outside the repository depends on the address.

**The repository rename is the owner's command, not this branch's.** `raydirect/web-spark` →
`raydirect/mr-spark` was attempted and refused: renaming needs `administration:write`, and the automation
token behind this work returns `403 Resource not accessible by integration`. So `gh repo rename
mr-spark --repo raydirect/web-spark` is on the owner's list, and `package.json.repository`, `homepage` and
the clone lines in `README`/`docs/WINDOWS.md` deliberately still say `web-spark`. That is not laziness about
a hyphen: a clone instruction that 404s is the same defect this change exists to remove — `npx webspark`
pointing at somebody else's package. After the rename, GitHub redirects the old path, so both names work and
the docs need no edit; before it, only the old one is real.

`test/install.test.js` already refuses to assert anything about the checkout directory's name — an earlier
version matched `/web-spark/`, passed in this clone, and failed in every worktree — which is why nothing in
the suite moves when the rename lands.

**The `mrspark` pointer package is a promise to keep two names in step**, which is a small tax and the
cheapest way to make "install the wrong thing" impossible. If maintaining it ever becomes the kind of
chore people skip, the fallback is to yank `mrspark` rather than let it drift, and a drifted pointer is
worse than an absent one.
